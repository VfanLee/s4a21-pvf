# 手动维护流程

返回 [数据库目录](README.md)。下列操作仅由你执行，AI 不连接数据库执行修改。

## 修改前

1. 确认实际数据库、表结构、目标角色或记录，以及需要保留还是重置的状态。
2. 停止服务端，备份实际 SQLite 数据库，并保存修改前的行值，避免进程缓存写回旧状态。
   WAL 模式下或不能停服时，不能只复制主文件当作完整备份，应使用一致性备份。
3. 根据定位键先查询，明确预期记录数和关联影响；不能只凭界面文字或名称猜编号。
   涉及 PVF 时，用当次目标包核对登记与定义。

## 修改与验证

1. 在事务中仅更新确认的记录和字段，保留无关状态；有版本或激活标识时按对应场景核对。
2. 立即检查影响行数和新值。匹配失败或结果不符就回滚，不扩大查询条件批量修改。
3. 核对后由你提交，保留修改清单和原值，以便按具体记录恢复。
4. 重新启动服务端；涉及 PVF 的场景加载对应包，通过正常游戏流程检查结果及相关功能。

不因修改 PVF 就批量重置数据库；不同场景的计数、实例和完成标记不能互相套用。
具体计算、更新条件和验收步骤见各场景页。
