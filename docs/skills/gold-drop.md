# 金币掉落

对应 [gold-drop 技能](../../.agents/skills/gold-drop/SKILL.md)。
先区分怪物掉落、场景可破坏物件掉落、通关翻牌金币与 NPC 买卖价格。
金币数量、出现概率和倍率分别控制。下列公式适用于本项目 A21 服务端。

## 配置

| PVF 文件与字段 | 实际作用 |
| --- | --- |
| `etc/itemdropinfo_common.etc` 的 `[gold drop ref table]` | 每组三个整数：等级、金币基数、浮动百分比；等级 1～200 |
| `etc/itemdropinfo_monseter.etc` 的 `[drop prob]` | 每行七个值；第 1～2 列为最低/最高等级，第 3 列为金币概率；保留第 4～7 列及 `monseter` 拼写 |
| 同文件的 `[monster type drop bonusrate]` | 5 类 × 4 种怪物类型；第一类的四个值乘金币概率 |
| `etc/itemdropinfo_object.etc` 的概率和加成表 | 金币为第 0 类，使用该类的难度与对象类型加成；当前物件类型索引是 0 |
| `etc/itemdropinfo_clearreward.etc` 的 `[dungeon difficulty gold drop bonusrate]` | 按难度索引控制翻牌金币数量倍率 |
| 同文件的 `[party member drop bonusrate]` | 按队伍人数控制翻牌金币倍率；计算个人收益时还会除以人数 |

通用金币表由怪物、随机物件掉落和普通翻牌共同使用，按调用方的怪物/物件等级或副本基准等级
取值。修改这张表会同时影响这些入口。

## 概率与数量怎么算

当前怪物掉落算法：

```text
类型概率值 = 取整(基础概率 × 怪物类型加成)
概率值 = min(取整(类型概率值 × 难度加成), 10000)
概率值 > LCG.Next(10000) 时掉金币
浮动 = 从 [-浮动百分比, +浮动百分比] 中抽一个整数
金币变化 = 浮动 × 金币基数 / 100，整数除法向零截断
金币数量 = max(1, 取整((金币基数 + 金币变化) × 难度加成))
```

概率分母是 10,000，750 表示名义上的 7.5%。当前怪物难度加成为代码写死的
`1、1.2、1.4、1.6、1.8`，对应索引 0～4，同时影响概率与数量。
这条掉落路径没有读取怪物文件中的难度和队伍加成表；`[gold quantity]`、`[gold volume]`、
副本 `[gold drop prob]` 未参与这条怪物金币掉落路径。

物件使用自己的概率及加成表，最高概率值为 10000，判定是 `LCG.Next(10001) < 概率值`。
名义概率为“概率值 / 10001”。物件金币数量共用通用金币表的
基数与浮动，不乘怪物那组硬编码难度倍率；非正结果保底为 1。

普通免费翻牌金币：

```text
加权击杀数 = 普通击杀数 + 2 × 精英击杀数 + 4 × BOSS 击杀数
个人金币 = 非负整数(
  金币基数 × 0.175 × 加权击杀数 / 2 × 难度倍率 × 队伍倍率
  × (1 + 评分加成) / 队伍人数)
随后应用通用金币表的浮动，结果限制为非负整数
```

没有有效击杀时为 0；负浮动结果保底为 0，怪物金币保底为 1。
`[gold card create rate]` 控制付费物品卡生成。
大会副本的 `[tournament clear reward gold rate]` 是直接倍率，16 表示 16 倍。
拾取应用装备金币加成和携带上限，需区分地面生成数额与最终入账数额。

## 修改和验收

- 调整数量倍数时，只乘目标等级行的金币基数，先明确取整方式；未要求则保留浮动列。
  调整概率时，只改对应金币概率列或已确认的加成项，保留物品概率列和表结构。
- 读取目标表，核对行数、等级范围/重复、加成索引、整数溢出、上限和极端浮动。
- 回读输出并比较非目标内容，核对清单路径。实机把金币出现频率和数量分别统计，
  再分别测试物件和翻牌；控制等级、难度、怪物类型、队伍人数、评分和装备加成。
