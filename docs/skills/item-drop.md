# 物品掉落与任务材料

## 修改边界与回读

- 闭合副本 → 地图 → 出场模板及物品/任务登记，先确认实际生成分支。
- 概率、权重、数量按各分支的单位解释；只改目标行列，保留其他来源、条件与道具类型。
- 共用模板和表可能影响多个副本；回读分组、候选 ID、概率/次数及未改记录。
- 固定副本策略、模板、难度与任务/持有状态验收，配置率不等于实测每趟出货率。

核查外部独立掉落书签时，先检查 `etc/independentdrop.lst` 及其子 `.etc` 的
正文是否非空，并追踪读取方；保留的空文件不代表外部掉落链已启用。
`etc/itemdictionary/(r)independentdropinfo.etc` 的 `[item table]`、`[list]`
属于词典展示数据，不能代替实际掉落生成配置。

## 全局材料掉落

`etc/worlddrop.etc` 的 `[world drop]` 按怪物等级分组：等级、一个保留整数、
若干“物品 ID、权重”对，最后以独立的 `-1` 结束。
关闭指定物品的全局掉落时，把所有匹配对的权重改为 `0`，保留物品 ID、等级头、
其他物品及结束标记。不能只删 ID，也不能把 ID 改成金币 `0`。
若移除完整的一对，必须保持后续配对不发生错位；改自动拾取列表不会关闭掉落。

“匹配多少处”应按解析后的物品 ID/权重对统计，并说明对应的怪物等级组，不能只数文本中的同一数字。
某个等级组存在但没有目标物品，不等于这个等级组不存在。解释排除的等级时，分别核对物品是否列入及其权重。
组的边界由独立的 `-1` 决定，不由编辑器换行决定。

参考 ServerS4A21 的 `WorldDropSystem` 忽略非正数 ID 或权重，按怪物等级选组，
生成范围为等级 1～199。正权重之和 W 作为与 `Next(100000)` 比较的触发阈值，
触发后按相对权重选一个物品并掉落一件；总权重也影响触发，不能擅自把取消的权重补给其他物品。
表会在进程内缓存，修改后客户端与服务端加载同一份 PVF，并重启服务端。
该修改只关闭全局表来源，怪物池、地区材料、独立掉落和任务奖励需分别核对。
回读时确认所有目标权重为零，其他条目未变；实机核对对应怪物等级的掉落。

对应 [item-drop 技能](../../.agents/skills/item-drop/SKILL.md)。以下运行规则适用于参考 ServerS4A21。

先通过各自 `.lst` 确认物品、怪物、任务和副本，再区分提高原有产量、增加新掉落来源、取消任务限制。
道具是 `[quest]` 还是 `[material]` 要读定义；不要为了加掉落随意改道具类型。

遇到多个同名怪物，按副本登记表 → `.dgn` 的 `[maze info]` / `[map specification]`
地图 ID → `map/map.lst` → 地图 `[monster]` 出场 ID → `monster/monster.lst` → `.mob`
逐步定位。核对范围时包含任务关联迷宫和候选地图；名称搜索结果或编辑器选中的同名文件
不能证明它就是该副本实际使用的模板。

覆盖英雄模式时另查地图的 `[heroes mode map index]`，并通过 `map/map.lst`
确认引用目标存在；仅有 Hero 前缀的怪物或地图文件不能证明当前副本会切换到它。

判断怪物身份或称号时，另查 `[monster title]` 的称号资源引用，不能仅凭掉落某种戒指判断身份。
同名怪物可能有普通、特殊或活动模板，角色名称数量与怪物 ID 数量不同；
修改副本掉落前仍需从地图确认实际出场 ID。

## 任务物品


`.qst` 的 `[monster reward item]` 每七个整数一组：

```text
怪物ID 副本ID 难度 物品ID 尝试次数 概率百分比 持有上限
```

副本和难度的 `-1` 表示不限，怪物 ID 必须精确匹配。只有已接任务参与匹配。
非负难度值按当前副本难度编号精确匹配，不表示最低难度；调用方原样传入当前难度。
普通五档副本使用编号 `0–4`，因此列出 `1–4` 时排除的是 `0`，已包含最高编号 `4`。
不能因为界面有五档就新增难度 `5`，也不要把多条难度行全部改成重复的 `-1` 行，
因为每条命中的行都会成为候选，可能改变选择行为。已包含的难度仍不掉落时，
应核对实际地图出场的怪物编号，而不是直接认定高难度被排除。
先确认该定义路径登记在 `n_quest/quest.lst` 中；参考 ServerS4A21通过此登记表加载任务，
仅存在于 PVF 中但未登记的 `.qst` 不会成为有效任务掉落来源。
每次尝试按 `Next(100) < 概率` 判断；增加尝试次数提高产量，概率为 100 时才每次成功。
实际持有上限还受收集任务 `[int data]` 所需数量限制，取两者适用值中较小者。
只提高行末上限不会改变收集目标。只加快收集时保留副本、难度与任务目标。
实机测试应接取任务，且持有量低于有效上限。

## 怪物普通掉落池

`.mob` 的 `[item]` 是“物品 ID、权重”成对重复，并以 `[/item]` 结束。
参考 ServerS4A21 先进行一次 10% 的共享掉落池判定，成功后按相对权重选一个物品，掉落 1 个。
启用并配置地区材料时，还会以权重 100 合并进同一个池；副本掉落策略也可能禁用这条路径。

提高权重只能提高物品在池中的占比，不能提高共享触发率，也不能提高单次数量。
没有其他来源合并时，单物品池增加权重没有收益。需要更高的绝对频率或数量，应另行检查
服务端支持的独立掉落配置；没有 PVF 实现路径时说明限制，服务端问题由用户自行处理。
怪物模板可能被多个副本共用，
不能未经地图引用核对就声称只影响某个副本。换电脑不改变同一实现的含义，
服务端实现有变化时才核对受影响的读取与调用逻辑。

共享触发率在 `ServerS4A21/Server/DfoServer/Game/Dungeon/DropGenerator.cs` 中，
由 `MobItemDropRate / DropDenominator` 决定，不是 PVF 字段，影响使用这条分支的所有
已启用掉落池。AI 仅说明该边界，不修改、编译或部署服务端。如果只提高某个物品，可检查
`etc/independent_drop.etc` 的直接物品独立掉落配置；它与原有掉落池分别判定，
需计算叠加后的实际概率，并考虑同次击杀重复掉落。

## 普通随机装备掉落

参考 ServerS4A21 的 `MonsterDropConfig` 只加载
`etc/itemdropinfo_monseter.etc`；C# 源码中没有
`etc/itemdropinfo_monseter_extra.etc` 的加载引用。
不能凭 `_extra` 文件名认定它会追加掉落、只控制精英怪或覆盖主表；
其他服务端实现需要另行核对加载与调用逻辑。

这个文件还控制普通金币和可堆叠物品掉落：`[drop prob]` 中类型1、类型3
都调用同一个可堆叠物品池，类型2才调用装备池；不能把类型1和类型3直接标为
不同的“材料池、卡片池”。可堆叠池从 `stackable.lst` 解析，要求 ID 大于2，
`[grade]` 和 `[creation rate]` 为正，并排除登记路径以 `cash/`、`quest/`、
`recipe/`、`temp/`、`event/`、`emblem/`、`monsterCard/` 开头的物品，不区分大小写。
此分支的 `[creation rate]` 只决定是否入池，不作为相对权重；匹配等级和稀有度的
候选等概率选择，目标稀有度没有候选时可回退到稀有度0。
因此 `monsterCard/` 卡片不能靠提高这张表或自身创建率加入普通池，具体卡片应另查
怪物定义、独立掉落或实际发放路径。材料可能同时有普通池及其他来源，修改此表
不能代替全局材料、地区材料、怪物定义或独立掉落配置的调整。



参考 ServerS4A21 的普通随机装备分支与怪物 `[item]` 池分开判定。
`etc/itemdropinfo_monseter.etc` 的 `[drop prob]` 每行七个值，第 1、2 列为等级范围，
第 5 列用于装备基础概率，第 7 列在这条实现中未解释。装备概率先乘
`[monster type drop bonusrate]` 中索引 2 类的对应怪物类型倍率，再乘难度索引
0–4 对应的 `1、1.2、1.4、1.6、1.8`；中间计算截断整数，最后上限和概率分母均为 10000。

触发后按 `[basis of rarity dicision]` 第 0 行抽稀有度，再根据
`[item drop ref table]` 的等级范围和装备池权重选物品。对应稀有度池为空时可能回退到稀有度 0，
最终候选为空则不掉装备。提高装备触发率不等于提高某种稀有度的抽中概率。
这个难度倍率不适用于怪物材料池，也不能直接套到深渊、独立掉落或翻牌装备。

普通怪物表的 `[basis of rarity dicision]` 连续保存四组，每组七个整数，
没有开头的组数。先把数字按顺序展开再每七个分组，编辑器换行可能拆开一组。
七列依次为稀有度编号 `0–6` 的累计上限，随机值范围 `1–1000000`，
按顺序用“小于等于”判断。各档概率取截断到随机范围后的相邻上限差值；
超过 `1000000` 的部分不增加概率。当前普通装备和可堆叠物品分支都固定使用第一组，
不会按难度或怪物类型切换后面三组，不给未使用组编造运行时分类。
深渊表采用另一套带开头组数的解析规则，不能混用。

## 普通通关翻牌物品

### 掉落表覆盖范围与特殊副本

参考 ServerS4A21 的 `itemdropinfo_*` 不涵盖全部奖励来源。先核对具体副本的
掉落策略与结算分支：普通策略还允许怪物 `.mob` 池、地区材料、独立掉落和全局掉落。
Impossible 策略只允许金币、独立掉落和异界怪物掉落来源，分类依据是 `.dgn`
`[impossible dungeon classification]` 及已验证的单人/组队共用关系，不能凭“远古”或活动名称判断。
执照副本关闭普通怪物来源，使用 `etc/dungeonetc/licensedungeoninfo.etc` 专用奖励。

异界使用 `etc/dimensiongatedroplist.etc` 按职业、转职组织的普通/套装异界装备池，
供专用怪物奖励与免费/付费物品卡使用；翻牌金币和付费价格仍使用通用结算配置。
深渊装备使用 `etc/itemdropinfo_monster_hell.etc`，但调用方还可能另外生成独立掉落与史诗碎片。
活动奖励要从具体副本、任务或特殊模式调用逻辑定位，不存在凭活动名称就能确定的统一掉落表。

### 深渊品质表的分组

参考 ServerS4A21 深渊随机装备分支按 `EquipmentDropLevelRule.TryGetAtlasGradeRange`
筛选候选：从副本 `[minimum required level]` 到 `[basis level]+7`，两端包含，
限制在1–200。比较的是装备 `[grade]`，不是穿戴 `[minimum level]`。
深渊表的 `[item drop ref table]` 虽然被解析，但当前候选选择函数没有使用它的范围方法。
不同区域共用创建率为正的装备池，应比较筛选后的史诗 ID 集合及权重，才能确定名单
是否相同。共用品质表不代表名单或每趟出货率必然相同；难度概率、尝试次数、药水重抽
及独立来源仍需分开核对。

`[dungeon difficulty drop prob]` 每七个整数一组：副本掉落基准等级下限、上限，
以及地下城难度编号 0～4 的五个装备触发值。它们不负责选择深渊品质表的组。
当前 `HellMonsterDropConfig` 固定基础倍率为 100；配置值不大于零时不触发，
正值按 `Next(1001) <= 配置值` 判定。因此小于 1000 的正值对应
`(配置值+1)/1001`，大于等于 1000 则必过。这是每次奖励尝试的装备触发概率，
不是每趟出货率或史诗率。该加载器不读取 `[drop prob count]`，尝试次数由调用方传入；
`[item drop rarity control]` 也未被这条分支读取，保留原值，不编造作用。
稀有度编号依次为普通、高级、稀有、神器、史诗、勇者、传说（0～6）；
当前深渊品质抽签只检查 0～5，第七个存储阈值不能开启传说抽签。

当前 `HellMonsterDropConfig` 读取 `etc/itemdropinfo_monster_hell.etc`
`[basis of rarity dicision]` 时，首个整数为组数，后续每七个整数构成一组。
换行不分组；若视觉上每行只写六个数，解析器会从下一行取第一个数，导致后续组错位。
每组只使用前六个数，作为稀有度 0～5 的累计阈值，随机范围为 1～1000000；
第七个数应保留，当前不参与品质抽签。
深渊难度 1（非常困难）选第 0 组，2（困难）选第 1 组，与地下城难度分开。
解释概率前先检查组数和实际七数分组。品质比例是通过掉落判定后的抽签比例，
史诗 Buff 重抽与候选为空时的回退还可能改变最终品质。

参考 ServerS4A21 的手动深渊入场，若请求未明确指定模式 1 或 2，会按
`etc/hellparty.etc [difficulty]` 中 A（非常困难）、B（困难）的非负
`Probability` 权重随机选择，不能默认各占一半。普通入场流程接受明确指定的模式；
成功准备华丽挑战时强制非常困难。选定模式保存在本次副本并复用，
掉落品质表不负责随机选择入场模式。

### 普通物品卡

翻牌表的 `[basis of rarity dicision]` 没有开头的组数，解析为一个平面的累计上限数组，
抽签按顺序检查所有已提供上限。不要套用深渊表每组七列的结构，保留实际数组长度。
超过 `1000000` 的上限本身不等于零概率占位：如果随机数能走到这一列，
它会接收所有剩余随机数；只有前一档已经覆盖到 `1000000` 时，这一档才没有区间。

参考 ServerS4A21读取 `etc/itemdropinfo_clearreward.etc`。`[drop prob]` 按档位名称记录
“等级下限、等级上限、基础概率”：免费物品卡用 `default`，付费卡用 `event`。
触发阈值为 `标准掉落率/100 ×（基础概率 × 地图系数 + 难度加值）×（1-死亡惩罚）`，
限于 0–10000，与 `Next(10000)` 比较。`[dungeon difficulty drop bonusrate]` 是加值，
不是乘数。免费卡地图系数为探索房间比例，再乘适用的
`[reward item rate per map max count]` 数值/10000；付费卡用 `[gold card create rate]`。
普通免费牌和付费牌通过出物品判定后，都进入同一套品质、类型和等级选择逻辑。
共用品质表表示抽品质的比例相同，不表示每次翻牌获得物品或某品质的最终概率相同。
档位基础数值还受地图系数、加值、惩罚和候选池影响，不能直接当成最终百分比。

触发后，`[drop item type prob]` 按相对权重抽类型，当前仅实现类型 2（装备）与 4（装扮）。
`[basis of rarity dicision]` 是对 1–1000000 随机数的累计阈值，各稀有度的区间由相邻阈值之差决定，
不是独立权重；超过 1000000 的阈值不会新增概率。随后按等级范围和翻牌装备池选物品，
候选为空则没有物品，不回退低稀有度。因此稀有度区间概率不等于每次翻牌的实际出货率。
`[item drop rarity control]` 虽被解析，但这条生成逻辑没有使用；
`[drop kind prob]` 和空卡物品标签也没有被这条路径读取。

`[item drop ref table]` 每组三个数为“副本基准等级、向下 grade 范围、向上 grade 范围”。
候选装备的 `[grade]` 范围是 `[基准等级-向下范围, 基准等级+向上范围)`，
左端包含、右端不包含，并限制在 1～200；不能用装备 `[minimum level]` 替代。
装备池要求 `[creation rate]` 和 `[grade]` 为正、稀有度为 0～5，
`[creation rate]` 是池内相对权重；装备与装扮分池。修改装备生成权重还会影响
共用的普通装备掉落池，不能当成只影响翻牌的开关。

`[gold card cost table]` 为“副本基准等级、付费翻牌金币价格”对；优先精确等级，
缺行时取最近的较低等级，没有较低等级则取最低等级。
普通翻牌解析与生成路径没有读取 `[drop prob count]` 和 `[chronicle set reward rate]`。
这些未支持字段应保留，不能凭标签名称承诺生效。

## 任务敌人掉落字段

参考 ServerS4A21 中，`.qst` 的 `[enemy reward item]` 每组八个整数：
`敌人代码 敌人类型 副本ID 难度 物品ID 判定次数 概率百分比 持有上限`。
敌人类型 `1` 为怪物，`2` 为 AI 角色/APC，`3` 为被动物件；代码与类型均需精确匹配。
副本 `-1` 表示任意副本，负数难度表示任意难度，否则精确匹配难度索引。
只有已登记且正在进行的任务提供候选。每次判定以 `Next(100) < 概率` 为成功条件，
成功一次产生一个物品；判定次数不等于必得数量，概率 100 时各次均成功。
持有量达到有效上限后停止产生，最后一次数量会截断至上限。
`[type] [seeking]` 下的 `[int data]` 为物品ID/需求数量对；有效掉落上限
取适用的持有上限与收集需求中较小值。`[condition message]` 是显示文字，
应与实际收集需求核对，不能用文字替代目标数量。

实际发放还经过参考服务端的任务助手加成：账号魔王契约的任务助手服务
（槽位索引 `2`）生效时，在基础数量上追加 `基础数量整除2` 个；基础数量
为奇数时再以 50% 概率追加一个。基础数量为偶数且距上限足够时，实际为
基础数量的 1.5 倍；最后仍按有效持有上限截断。服务状态在本次副本内缓存。
该加成来自服务端和账号契约状态，不能只读 `.qst` 的基础数量便断言最终数量。

## 地图可破坏物件的指定材料掉落

按副本登记表 → `.dgn` `[special passive object item]` → 迷宫地图登记表 →
`.map` `[special passive object]` 的生成动作闭合来源。
副本组结构为 `组号 等级覆盖值 候选数 (物品ID 权重)...`，候选数不是掉落数量，
组号必须从 0 连续排列；参考解析器遇到重复标签或格式错误会禁用该定义。
此元数据读取路径还只读取首个数据行，另起一行的后续编号组不会加载；
解释概率前应核对标签数量及实际解析出的组。
同名标签也可能分别位于不同 `[maze info]` / `[quest connection]` 段后，
应区分原文的迷宫上下文与参考 PvfLib 解析器只支持单定义的限制，不能据此认定 PVF 本身损坏，
也不能在未验证部署端迷宫作用域时直接合并或移除。
同一标签内的多个编号组是供地图动作引用的不同物品池，不是重复奖励或数量。

物件 `[item]` 动作为 `组号 指定抽取次数 随机抽取次数 参数1 参数2`。
当前指定分支使用前两个整数，每次独立抽取成功发 1 个物品；随机抽取另走
`etc/itemdropinfo_object.etc`。不能把增加尝试次数解释为保证掉落相同数量。
指定分支用 `Next(10001)` 与累计非负权重比较，条件为“小于”；只有一个候选且
权重 w 不超过 10000 时，每次概率为 w/10001。权重不归一化，剩余区间不掉物品，
前面候选的区间会影响后面候选。

提高副本组权重调整概率，提高地图动作指定抽取次数增加尝试次数；地图可能被多个副本共用。
来源查询分别检查箱子、怪物、独立掉落与礼包奖励，配方输入、入场消耗和道具说明不是掉落证据。

## 指定怪物的直接独立掉落

参考 ServerS4A21在 `etc/independent_drop.etc` 中支持 17 个整数的直接物品行：

```text
0 怪物ID 物品ID 概率0 概率1 概率2 概率3 概率4 数量0 数量1 数量2 数量3 数量4 等级下限 等级上限 难度 0
```

五列概率对应难度索引 0–4，概率分母为 1000000。参考生成器始终读数量0，组队也如此。
等级指副本基准等级，只有上下限都为正时才过滤；难度 `-1` 表示不限。
这个格式没有副本 ID 列，同一个怪物模板在多个副本出现时都可能匹配，且需副本掉落策略启用该分支。
怪物 ID 必须来自 `monster/monster.lst`，不能用 NPC 或 APC 的编号代替。
人形敌人不一定是 APC，真正的 AI 角色要另查其击杀掉落路径。
独立掉落不要求接任务，与原有怪物池分别判定，可同时掉物品；实机核对实际出场模板、数量和频率。
