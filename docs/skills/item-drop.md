# 物品掉落与任务材料

## 全局材料掉落

`etc/worlddrop.etc` 的 `[world drop]` 按怪物等级分组：等级、一个保留整数、
若干“物品 ID、权重”对，最后以独立的 `-1` 结束。
关闭指定物品的全局掉落时，把所有匹配对的权重改为 `0`，保留物品 ID、等级头、
其他物品及结束标记。不能只删 ID，也不能把 ID 改成金币 `0`。
若移除完整的一对，必须保持后续配对不发生错位；改自动拾取列表不会关闭掉落。

“匹配多少处”应按解析后的物品 ID/权重对统计，并说明对应的怪物等级组，不能只数文本中的同一数字。
某个等级组存在但没有目标物品，不等于这个等级组不存在。解释排除的等级时，分别核对物品是否列入及其权重。
组的边界由独立的 `-1` 决定，不由编辑器换行决定。

当前 ServerS4A21 的 `WorldDropSystem` 忽略非正数 ID 或权重，按怪物等级选组，
生成范围为等级 1～199。正权重之和 W 作为与 `Next(100000)` 比较的触发阈值，
触发后按相对权重选一个物品并掉落一件；总权重也影响触发，不能擅自把取消的权重补给其他物品。
表会在进程内缓存，修改后客户端与服务端加载同一份 PVF，并重启服务端。
该修改只关闭全局表来源，怪物池、地区材料、独立掉落和任务奖励需分别核对。
回读时确认所有目标权重为零，其他条目未变；实机核对对应怪物等级的掉落。

对应 [item-drop 技能](../../.agents/skills/item-drop/SKILL.md)。以下运行规则适用于本项目当前 ServerS4A21。

先通过各自 `.lst` 确认物品、怪物、任务和副本，再区分提高原有产量、增加新掉落来源、取消任务限制。
道具是 `[quest]` 还是 `[material]` 要读定义；不要为了加掉落随意改道具类型。

遇到多个同名怪物，按副本登记表 → `.dgn` 的 `[maze info]` / `[map specification]`
地图 ID → `map/map.lst` → 地图 `[monster]` 出场 ID → `monster/monster.lst` → `.mob`
逐步定位。核对范围时包含任务关联迷宫和候选地图；名称搜索结果或编辑器选中的同名文件
不能证明它就是该副本实际使用的模板。

覆盖英雄模式时另查地图的 `[heroes mode map index]`，并通过 `map/map.lst`
确认引用目标存在；仅有 Hero 前缀的怪物或地图文件不能证明当前副本会切换到它。

判断怪物身份或称号时，另查 `[monster title]` 的称号资源引用，不能仅凭掉落某种戒指判断身份。
同名怪物可能有普通、特殊或活动模板，角色名称数量与怪物 ID 数量不同；
修改副本掉落前仍需从地图确认实际出场 ID。

## 任务物品


`.qst` 的 `[monster reward item]` 每七个整数一组：

```text
怪物ID 副本ID 难度 物品ID 尝试次数 概率百分比 持有上限
```

副本和难度的 `-1` 表示不限，怪物 ID 必须精确匹配。只有已接任务参与匹配。
每次尝试按 `Next(100) < 概率` 判断；增加尝试次数提高产量，概率为 100 时才每次成功。
实际持有上限还受收集任务 `[int data]` 所需数量限制，取两者适用值中较小者。
只提高行末上限不会改变收集目标。只加快收集时保留副本、难度与任务目标。
实机测试应接取任务，且持有量低于有效上限。

## 怪物普通掉落池

`.mob` 的 `[item]` 是“物品 ID、权重”成对重复，并以 `[/item]` 结束。
当前服务端先进行一次 10% 的共享掉落池判定，成功后按相对权重选一个物品，掉落 1 个。
启用并配置地区材料时，还会以权重 100 合并进同一个池；副本掉落策略也可能禁用这条路径。

提高权重只能提高物品在池中的占比，不能提高共享触发率，也不能提高单次数量。
没有其他来源合并时，单物品池增加权重没有收益。需要更高的绝对频率或数量，应另行检查
服务端支持的独立掉落配置，或明确授权修改服务端。怪物模板可能被多个副本共用，
不能未经地图引用核对就声称只影响某个副本。其他部署的服务端需重新验证数值含义。

共享触发率在 `ServerS4A21/Server/DfoServer/Game/Dungeon/DropGenerator.cs` 中，
由 `MobItemDropRate / DropDenominator` 决定，不是 PVF 字段。修改常量会影响使用这条
分支的所有已启用掉落池，需重新编译并部署服务端。如果只提高某个物品，可检查
`etc/independent_drop.etc` 的直接物品独立掉落配置；它与原有掉落池分别判定，
需计算叠加后的实际概率，并考虑同次击杀重复掉落。

## 普通随机装备掉落

本项目当前 ServerS4A21 的 `MonsterDropConfig` 只加载
`etc/itemdropinfo_monseter.etc`；C# 源码中没有
`etc/itemdropinfo_monseter_extra.etc` 的加载引用。
不能凭 `_extra` 文件名认定它会追加掉落、只控制精英怪或覆盖主表；
其他服务端实现需要另行核对加载与调用逻辑。



当前服务端的普通随机装备分支与怪物 `[item]` 池分开判定。
`etc/itemdropinfo_monseter.etc` 的 `[drop prob]` 每行七个值，第 1、2 列为等级范围，
第 5 列用于装备基础概率，第 7 列在这条实现中未解释。装备概率先乘
`[monster type drop bonusrate]` 中索引 2 类的对应怪物类型倍率，再乘难度索引
0–4 对应的 `1、1.2、1.4、1.6、1.8`；中间计算截断整数，最后上限和概率分母均为 10000。

触发后按 `[basis of rarity dicision]` 第 0 行抽稀有度，再根据
`[item drop ref table]` 的等级范围和装备池权重选物品。对应稀有度池为空时可能回退到稀有度 0，
最终候选为空则不掉装备。提高装备触发率不等于提高某种稀有度的抽中概率。
这个难度倍率不适用于怪物材料池，也不能直接套到深渊、独立掉落或翻牌装备。

## 普通通关翻牌物品

### 掉落表覆盖范围与特殊副本

本项目当前服务端的 `itemdropinfo_*` 不涵盖全部奖励来源。先核对具体副本的
掉落策略与结算分支：普通策略还允许怪物 `.mob` 池、地区材料、独立掉落和全局掉落。
Impossible 策略只允许金币、独立掉落和异界怪物掉落来源，分类依据是 `.dgn`
`[impossible dungeon classification]` 及已验证的单人/组队共用关系，不能凭“远古”或活动名称判断。
执照副本关闭普通怪物来源，使用 `etc/dungeonetc/licensedungeoninfo.etc` 专用奖励。

异界使用 `etc/dimensiongatedroplist.etc` 按职业、转职组织的普通/套装异界装备池，
供专用怪物奖励与免费/付费物品卡使用；翻牌金币和付费价格仍使用通用结算配置。
深渊装备使用 `etc/itemdropinfo_monster_hell.etc`，但调用方还可能另外生成独立掉落与史诗碎片。
活动奖励要从具体副本、任务或特殊模式调用逻辑定位，不存在凭活动名称就能确定的统一掉落表。

### 深渊品质表的分组

当前 `HellMonsterDropConfig` 读取 `etc/itemdropinfo_monster_hell.etc`
`[basis of rarity dicision]` 时，首个整数为组数，后续每七个整数构成一组。
换行不分组；若视觉上每行只写六个数，解析器会从下一行取第一个数，导致后续组错位。
每组只使用前六个数，作为稀有度 0～5 的累计阈值，随机范围为 1～1000000；
第七个数应保留，当前不参与品质抽签。
深渊难度 1（非常困难）选第 0 组，2（困难）选第 1 组，与地下城难度分开。
解释概率前先检查组数和实际七数分组。品质比例是通过掉落判定后的抽签比例，
史诗 Buff 重抽与候选为空时的回退还可能改变最终品质。

### 普通物品卡

当前服务端读取 `etc/itemdropinfo_clearreward.etc`。`[drop prob]` 按档位名称记录
“等级下限、等级上限、基础概率”：免费物品卡用 `default`，付费卡用 `event`。
触发阈值为 `标准掉落率/100 ×（基础概率 × 地图系数 + 难度加值）×（1-死亡惩罚）`，
限于 0–10000，与 `Next(10000)` 比较。`[dungeon difficulty drop bonusrate]` 是加值，
不是乘数。免费卡地图系数为探索房间比例，再乘适用的
`[reward item rate per map max count]` 数值/10000；付费卡用 `[gold card create rate]`。

触发后，`[drop item type prob]` 按相对权重抽类型，当前仅实现类型 2（装备）与 4（装扮）。
`[basis of rarity dicision]` 是对 1–1000000 随机数的累计阈值，各稀有度的区间由相邻阈值之差决定，
不是独立权重；超过 1000000 的阈值不会新增概率。随后按等级范围和翻牌装备池选物品，
候选为空则没有物品，不回退低稀有度。因此稀有度区间概率不等于每次翻牌的实际出货率。
`[item drop rarity control]` 虽被解析，但这条生成逻辑没有使用；
`[drop kind prob]` 和空卡物品标签也没有被这条路径读取。

`[item drop ref table]` 每组三个数为“副本基准等级、向下 grade 范围、向上 grade 范围”。
候选装备的 `[grade]` 范围是 `[基准等级-向下范围, 基准等级+向上范围)`，
左端包含、右端不包含，并限制在 1～200；不能用装备 `[minimum level]` 替代。
装备池要求 `[creation rate]` 和 `[grade]` 为正、稀有度为 0～5，
`[creation rate]` 是池内相对权重；装备与装扮分池。修改装备生成权重还会影响
共用的普通装备掉落池，不能当成只影响翻牌的开关。

`[gold card cost table]` 为“副本基准等级、付费翻牌金币价格”对；优先精确等级，
缺行时取最近的较低等级，没有较低等级则取最低等级。
普通翻牌解析与生成路径没有读取 `[drop prob count]` 和 `[chronicle set reward rate]`。
这些未支持字段应保留，不能凭标签名称承诺生效。

## 指定怪物的直接独立掉落

当前服务端在 `etc/independent_drop.etc` 中支持 17 个整数的直接物品行：

```text
0 怪物ID 物品ID 概率0 概率1 概率2 概率3 概率4 数量0 数量1 数量2 数量3 数量4 等级下限 等级上限 难度 0
```

五列概率对应难度索引 0–4，概率分母为 1000000。当前生成器始终读数量0，组队也如此。
等级指副本基准等级，只有上下限都为正时才过滤；难度 `-1` 表示不限。
这个格式没有副本 ID 列，同一个怪物模板在多个副本出现时都可能匹配，且需副本掉落策略启用该分支。
怪物 ID 必须来自 `monster/monster.lst`，不能用 NPC 或 APC 的编号代替。
人形敌人不一定是 APC，真正的 AI 角色要另查其击杀掉落路径。
独立掉落不要求接任务，与原有怪物池分别判定，可同时掉物品；实机核对实际出场模板、数量和频率。
