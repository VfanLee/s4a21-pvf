# 副本难度与入口

对应 [dungeon-difficulty 技能](../../.agents/skills/dungeon-difficulty/SKILL.md)。
通用打包、授权和改动清单规则见 [README.md](README.md)。本页限定于本项目 A21。

## 先找到配置

`dungeon/dungeon.lst` 是“副本 ID → 相对文件路径”的登记表，具体配置在对应 `.dgn` 中。
同名副本可能有普通、任务、活动和旧版等不同定义，不能只凭名字选文件。

| 位置或字段 | 如何处理 |
| --- | --- |
| `monster/monsterapcdifficultybonus.tbl` | 全局默认难度表 |
| `.dgn` 的 `[monsterapc diff table]` | 显式引用另一张表，确认引用文件存在 |
| `[monster difficulty bonus]` | 单独检查，不与独立表引用混为一谈 |
| `[difficulty]`、`[difficulty level]`、`[designate dungeon difficulty]` | 检查目标副本的难度相关配置 |

查询独立表时按引用路径分组，统一路径分隔符并忽略大小写。
多个副本可以共用同一张“独立表”，改动前应列出共同引用的副本。
仅凭引用字段不能证明全局与局部加成是叠加还是替代，需核对实际读取逻辑。

## 怪物等级与镜像阿拉德

登记表相对路径要先统一斜杠，再读取 PVF。镜像阿拉德按世界地图登记副本 ID
定位入口 `.dgn`，并通过 `etc/crackofdimensionlist.etc` 的 `[crack info list]`
“副本 ID、任务 ID”配对，继续读取实际历史副本与已登记任务。
分别检查 `[mob level charac level replace flag]`、`[basis level]`、
`[crack of dimension dungeon]`、`[revision table]` 与地图怪物等级字段。

当前 ServerS4A21 解析了角色等级替换标志，但没有该属性的实际调用引用，
不能承诺 0/1/2 各自实现某种已验证的缩放行为。普通怪物投影逻辑中，地图 Lv 非零时
取“副本 basis level + AutoLv”，Lv 为零时取绝对 AutoLv；结果非正时回退到副本基准等级。
任务与地图的配对、按角色等级发任务奖励，不能证明怪物等级跟随任务等级。
角色等级替换或修正表公式应在实际部署中另行验证。

## 剧情模式

本项目 A21 的剧情地下城在**简单模式**下，与普通图的难度行为一致，使用全局难度表
`monster/monsterapcdifficultybonus.tbl`，修改白图第一块也会影响该模式。
这条规则仅限简单模式，不推广到其他剧情难度，也不能仅凭“简单”名称认定具体列号；
目标副本若有独立表引用，仍需另行核对。

其他剧情难度还需检查 `monster/storymodedifficultybonus.tbl`，同时核对全局表和副本的独立表引用。
通过已登记 `.dgn` 的 `[story mode]` 确认模式，不能只凭副本名字或任务目录判断。
该段可包含 `[difficulty size]`、`[first difficulty rate]`、`[increase difficulty rate]`、
`[increase exp rate]` 和 `[quest list]`；当前解析器会保留这些数组及任务关联。
解析到字段不等于已经确认战斗倍率公式；除已确认的简单模式外，不能直接承诺修改白图第一块就会改变剧情难度，
也不能在未验证读取逻辑或实机表现时认定剧情表替代或乘算全局表。
经验倍率与怪物战斗难度需分别检查。

## 全局表前四块

本项目已检查的 A21 表头结构如下，实际修改前仍要核对目标文件结构：

| 区块 | 数值位置，从 1 开始 | 属性组数 | 每组数值个数 | 用途 |
| --- | --- | --- | --- | --- |
| 第一块 | 1～65 | 13 | 5 | 普通副本（白图） |
| 第二块 | 66～130 | 13 | 5 | 未确认 |
| 第三块 | 131～182 | 13 | 4 | 未确认 |
| 第四块 | 183～234 | 13 | 4 | 未确认 |

位置只统计表头无标签部分的数值，不包含文件头和注释。
编辑器的换行不等于属性分组；统一按五个数换行，会把后两块的四列分组拆开。
查看时可以重新排版，但数值顺序和整数、浮点类型不能改变。

只调整白图时，先检查目标副本是否引用独立表，再把全局改动限定在第一块。
其余三块不能直接标成塔、怪物/APC 或普通怪/精英/Boss。
确认第一块是白图，不代表每一行属性或每一列难度名称都已核实。

`[dungeon party balance]`、各难度标签及 `[adjust hp gauge]` 是后续独立段落，
不能继续按表头分组解释；血条显示数量也不能直接证明实际血量。
独立表需读取完整结构，不能默认与全局表有相同的表头长度。

## 修改比例与原版对比

对于已确认的倍率字段，按“新倍率 = 原倍率 × 调整比例”修改。
把原倍率乘以 `0.5` 才是减半，直接改成 `0.5` 不一定是当前效果的一半。
概率、抗性、速度、加算值和阈值需分别确认含义，不能统一缩放整张表。

使用 PVF 解析工具读取完整词元。当前工具的 `TableFile.Parse` 只保留
`long.TryParse` 能解析的值，会漏掉浮点数；Type 1 的整数词元类型为 0，浮点为 2。
对比标签、字符串、数值、顺序和数值类型，空白变化或字符串引用偏移变化不等于玩法变化。
有插入或删除时，先按段落和属性组对齐，不能把后续位置偏移全部算成数值修改。

以用户指定的原版为基线，按内部路径对比：

- 难度表内容、增加或移除，以及已登记副本的共同引用。
- `.dgn` 难度字段；整个档案的审计还包含未登记定义和未被引用的难度表。
- 登记表变化，单独记录；新增登记可能指向原版已有且未修改的 `.dgn`。

报告应包含表路径、段落/组/列、旧值、新值和涉及副本。
只比较难度表与 `.dgn` 时，不能据此断言单体怪物属性、基础属性表、技能伤害或脚本机制也未改。

## 旧副本是否开放

列出 A21 可手动挑战的深渊时，先核对已登记城镇入口和世界地图区域，再核对
区域 `[hell dungeon] 1`、`[hell quest]` 解锁任务，以及副本迷宫实际的深渊房间。
检查 `[seal door map index]` 和 `[seal door pos]`，通过 `map/map.lst` 找到地图并
确认有 `[hellparty]` 内容；文件名含坐标的 `hell_` 地图是另一条运行时回退路径。
仅有区域或副本的深渊开关不能证明可进入。

世界地图副本条目按“副本 ID、可选 `[in progress]`、任务 ID”跨行解析，任务专用
变体单独列出。本项目服务端要求区域所有正数深渊任务 ID 均已完成，即使某个
ID 在 `quest.lst` 中缺失也不会自动放行；缺失登记应报告为解锁链缺口。已有角色
的任务完成记录可能不同，静态查询不能替代角色实测。

解锁任务的可接等级与每个副本的入场等级应分别说明。静态核对只证明配置的
解锁链，不能写成已实机验证开放。区域有深渊标志却未核实深渊房间的特殊图、
活动入口，应与常规手动深渊分开列出。

区分“定义文件存在”“副本登记存在”和“入口配置闭合”：

```text
已登记城镇 .twn 的 [dungeon gate] 区域 ID
→ worldmap/worldmap.lst
→ 对应 .wdm 的 [dungeon] 副本引用及条件
```

档案中保留但未登记的 `.wdm` 不证明区域开放。
也要检查自定义区域，旧副本 ID 可以被新入口复用。
静态入口链不能证明角色满足进入条件、客户端资源齐全或服务端支持。

修改后回读确认只有计划内的路径、组和列改变，客户端与服务端加载同一份 PVF并重启服务端。
实机验证时固定副本、难度、人数、角色和装备，检查目标效果。
需要确认读取关系时，可以在获准修改后用单个字段的小幅变化验证；不能把尚未实测的改动写成已验证结论。
