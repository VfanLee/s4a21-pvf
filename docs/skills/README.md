# 怎么改 PVF

对应 [`.agents/skills/SKILL.md`](../../.agents/skills/SKILL.md)。结构先看 [../structure.md](../structure.md)。

## 适用范围与一致执行

同需求、同目标与同实现应采用一致的字段解释、修改范围及验证标准，工具和步骤可不同。

| 情况 | 处理规则 |
| --- | --- |
| 已提供或明确指定 PVF/解包目录 | 只读该目标的实际 ID、数值及引用；不自动选本地底板 |
| 没有指定目标 | 只按已有技能回答，说明未核实实际配置；知识缺失则说不确定、无法提供可靠结论 |
| 技能、目标与代码冲突 | 先调查并说明影响；方案变化后与用户决定，不静默修复无关内容 |
| 工具不可用 | 说明具体限制，停止依赖该工具的读写；不把包当文本改，不擅自安装依赖 |
| 三个参考项目 | ServerS4A21、S4A21ClientPatch、S4A21GmTool 默认只读；代码问题由用户处理 |
| custom-pvf | 用户手动维护，AI 仅按需只读；不写入、整理、改名、删除或自动套用 |
| 数据库 | 仅用户修改；AI 可解释代码和提供手动示例，不写数据或代跑修复脚本 |
| 确认了新规则或旧记录错误 | 直接同步修正技能与中文速查，不记录猜测或一次性配置值 |

区分配置格式、目标实际内容与参考代码行为。索引是定位入口，不证明文件启用；
GM/工具解析不完整不等于 PVF 格式错误。不同工具可能改变空白，回读核对 token 类型、
数值、顺序和引用，只允许授权字段及路径变化。配置回读与游戏验收分别报告。
专题提供配置入口、字段单位、修改边界、关联影响和验证方法；数据库维护见
[数据库参考目录](../database/README.md)，不作为 Agent 执行授权。

## 冒险团升级（A21）

参考 ServerS4A21 读取 `etc/linksystem/charactermanage.etc`。
`[point bonus]` 每组三列为等级下限、等级上限、每级贡献积分；账号中每个
未删除角色贡献所有不高于自身等级的配置积分之和，再汇总为账号积分。
这不是独立累积的刷图经验计数器。`[manage level point]` 按冒险团等级从 1 起
排列累计积分门槛，保留非负且严格递增。降低门槛可减轻升级要求，
不必同时修改角色贡献与等级福利。`[manage level max]` 限制最终等级；
`[exp bonus]`、`[gold bonus]` 是角色收益加成，不是冒险团升级成本。
`[manage option]` 是独立福利字段，仅改门槛时保持原值。
配置由服务端进程缓存，客户端和服务端加载同一份 PVF 并重启后，
返回角色选择或重新登录，核对重算后的账号冒险团等级。

## 支援兵配置（参考 ServerS4A21）

| 路径 | 字段/读取行为 |
| --- | --- |
| `etc/linksystem/charactermanage.etc` | 冒险团升级门槛，按上一节处理 |
| `etc/linksystem/characlinksystem.etc` | `[link level]` 及低/高联动角色经验、金币加成，不是升级门槛 |
| `etc/characlinksystem.etc` | `StrikerSkillDataProvider` 要求 `[2nd link character info]` 为七个整数，第七列为最低支援等级；未得到有效正等级时回退 `[1st link character info]` |
| `etc/linksystem/striker.etc` | `[striker combo]` 为最大启用支援兵数量 |

相似文件名不能互相替代；只改要求的门槛/数量，保留收益、时间和技能字段。
回读实际值，加载同一 PVF 并重启后，验收支援兵选择与数量限制。

## 硬规则

- 默认只读。没有明确授权：不写 PVF、不改客户端 ImagePacks2/NPK、不覆盖原版包。
- 数字 ID 不是事实，必须经正确 `.lst` 解析后再读文件。
- 新道具必须同时有空闲 ID、`.lst` 行、定义文件。改名字不会分配 ID。
- 新增块或新文件：先对照同目录、同扩展名、同用途的 2–3 个近邻。不要凭标签名想象格式。
- 保留原有标签、反引号、数值顺序和成对 `[/...]`；可编辑文本保留空白。
  Type 1 二进制 PVF 可能规范化回读的空白，应比较解析后的内容与顺序，并说明排版限制。
  不要把文档示例粘成完整文件。
- `.shp` 只上架。价格、绑定、效果、期限在道具文件。
- `[explain]` 是说明文字，不等于效果。图标路径不证明客户端资源存在。
- 重写打包 PVF 时，必须用 PVF 解析/写入工具：先保存临时档案、回读验证，最后原子替换已授权目标；不能把 PVF 当文本改。
- 写完必须读回。行为结论要说明实机怎么测。客户端和服务端加载同一份新 PVF；重启服务端是已确认的缓存清理方式，重载只在部署环境已验证支持时使用。
- 查询或修改确认了新的可复用知识，交付前同一轮更新对应技能/AGENTS.md 及中文页。
  直接记录操作规则和字段含义，保留必要的版本/运行环境范围；不写来源叙述、历史案例、
  参考包名称、一次性数值或不确定的解释，不依赖旧任务附件。新主题补齐两边入口。

## 字符串编码检查

S4A21 次元彼端 格式的 Type 1 字符串引用通过偏移的最低位区分窄字符串表 `sTrA`
和 UTF-16LE 表 `sTrW`。窄表可能包含旧式 GBK 字节，不能一律按 UTF-8 解码。
排查乱码时，比较原始字节以及来源字符串的引用类型。

迁移中文文本时保留 Unicode 引用；写入器复用字符串缓存时，可能选中窄表同名文本，
丢失来源中的 Unicode 表示。强制 Unicode 写入后检查引用偏移最低位为 1；
允许回退到窄表缓存的“优先 Unicode”选项不足以保证这一点。
名称和说明必须按使用端的解码方式验证，不能只依赖写入器自己的回读。
损坏文本从完整来源恢复，不猜字替换。

## 本项目输出与改动清单

- 保留输入包和基线包。没有另外指定时，新包放在本项目 `dist/`，名称为
  `Script_yyyyMMdd_HHmmss.pvf`，使用北京时间（UTC+8）。先写临时包并回读验证，
  再发布新文件；同名已存在时使用新时间，不覆盖已有输出。
- 用户明确要求直接更新原 PVF 时，以原地更新要求为准。修改前将当前目标备份到指定
  备份目录，文件名带北京时间后缀；重名追加序号，绝不覆盖旧备份。验证备份与当前输入
  一致，并保留目标已有改动，不能改用参考包重建整个目标。
- 实际修改 PVF 时，默认继续使用同一个 `dist/改动清单.xlsx`。用户指定记录目录时，
  将已有工作簿历史完整继承到指定目录，新的 CSV、JSON、Excel 和辅助报告也统一放在该目录。
  保留旧工作表，按修改功能新建工作表。
  A1 记录交付的 PVF 文件名，A2 简述改动内容，第 3 行为明细表头。
  A3 固定为“路径”，第 4 行起逐行记录实际修改或新增的 PVF 内路径，并去重。
  特殊改动有必要时可增加已核实的补充列，例如新增 ID 范围、兑换规则；文件路径始终必填。
  同名功能工作表已存在时加唯一后缀，并告知实际名称，不能替换历史记录。
- 核对工作表路径集合与实际改动一致，包含改动的登记表和配置文件。
  仅修改技能/文档不新增 PVF 改动工作表；历史商品支持分析表不作为改动清单更新。
- 交付修改后的脚本时，从已重新打开验证的 PVF 导出完整定义，在独立输出根目录下保留
  PVF 内部的目录和文件名，拒绝越过输出根目录的路径。正文使用可阅读的 UTF-8，
  正确处理窄表/Unicode 编码和反引号转义；重新解析导出文件，核对 token 类型、数值和
  字符串内容，浮点数即使看似整数也保留浮点写法。解包空白可能规范化，辅助文件与脚本目录分开。

## 流程

```text
只读闭合 →（授权后）最小改动 → 读回 → 打包匹配的客户端/服务端 PVF → 实机验收
```

1. 确认改的是 NPC / 道具 / 商店 / 其他，以及这次能不能写。
2. 用名称或 ID 走对应 `.lst`，读目标文件，不要靠文件名猜。
3. 列出路径、字段、旧值、新值，以及商店、配方、任务、礼包等依赖。
4. 获授权后再改，只改计划内字段。
5. 读回改动文件和相关 `.lst`。
6. 记录：改了什么、没改什么、打包注意、实机怎么验、旧道具实例会不会自动刷新。
